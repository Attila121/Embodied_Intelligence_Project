# Simulation setup and checklist

Use Ubuntu 22.04, ROS 2 Humble, and Gazebo Classic. This reproduces the project's working simulation setup. Gazebo Classic is a legacy stack; the Jazzy instructions use a different simulator and are not interchangeable.

## Install once

- [ ] Install ROS 2 Humble Desktop using the [official Ubuntu instructions](https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html).
- [ ] Install dependencies after configuring the ROS apt repository:

```bash
sudo apt update
sudo apt install ros-humble-gazebo-ros-pkgs \
  ros-humble-turtlebot3 ros-humble-turtlebot3-msgs \
  ros-humble-cartographer ros-humble-cartographer-ros \
  ros-humble-nav2-map-server python3-colcon-common-extensions \
  python3-rosdep python3-tk git
```

- [ ] Reuse an existing compatible workspace, or build the official Humble simulation:

```bash
mkdir -p ~/turtlebot3_ws/src
cd ~/turtlebot3_ws/src
git clone -b humble https://github.com/ROBOTIS-GIT/turtlebot3_simulations.git
cd ~/turtlebot3_ws
source /opt/ros/humble/setup.bash
# Run sudo rosdep init only if rosdep is not already initialized.
rosdep update
rosdep install --from-paths src --ignore-src --rosdistro humble -r -y
export MAKEFLAGS=-j1 CMAKE_BUILD_PARALLEL_LEVEL=1
colcon build --symlink-install --parallel-workers 1 --cmake-args -DCMAKE_BUILD_TYPE=Release
```

See [ROBOTIS simulation setup](https://docs.robotis.com/docs/systems/turtlebot3/simulation/gazebo_simulation/) for prerequisites. Do not clone over an existing checkout. Both package and compiler parallelism are limited here to reduce memory use.

The launcher sources `/opt/ros/humble/setup.bash` and `~/turtlebot3_ws/install/setup.bash` if present. For another workspace, set `TB3_WORKSPACE` to its absolute path in each terminal.

On Windows, open Ubuntu with `wsl -d Ubuntu-22.04`, then `cd` to your repository's Linux path. GUI applications need working WSLg or another configured Linux display.

## Run each session

From the repository root in separate Ubuntu terminals:

- [ ] Check packages: `bash scripts/run_ros_experiment.sh check`.
- [ ] Start Gazebo: `bash scripts/run_ros_experiment.sh world`. Wait for the world and robot; keep the simulation playing.
- [ ] Start mapping/RViz: `bash scripts/run_ros_experiment.sh slam`.
- [ ] Open controls: `bash scripts/run_ros_experiment.sh teleop`. Keep focus on the control window.
- [ ] Drive with held W/S and A/D; release to stop. Use only one controller.
- [ ] Inspect topics: `bash scripts/run_ros_experiment.sh topics`.

The launcher sets `TURTLEBOT3_MODEL=waffle_pi`, `ROS_DOMAIN_ID=30`, and `ROS_LOCALHOST_ONLY=1`. It configures its own process, not the parent shell. Direct ROS commands in an inspection terminal need:

```bash
source /opt/ros/humble/setup.bash
source ~/turtlebot3_ws/install/setup.bash
export ROS_DOMAIN_ID=30 ROS_LOCALHOST_ONLY=1
ros2 topic info /scan --verbose
ros2 topic echo /scan --once --field header --qos-reliability best_effort
ros2 topic echo /odom --once --field pose
ros2 topic echo /clock --once
ros2 topic echo /map --once --field info --qos-durability transient_local
ros2 run tf2_ros tf2_echo map base_footprint
```

Substitute your actual workspace path if different. Press `Ctrl+C` to stop continuous or waiting commands.

| Interface | Purpose |
| --- | --- |
| `/scan` | LiDAR ranges, `sensor_msgs/msg/LaserScan` |
| `/cmd_vel` | Requested speed, `geometry_msgs/msg/Twist` |
| `/odom` | Estimated motion, `nav_msgs/msg/Odometry` |
| `/clock` | Simulation time |
| `/map` | Occupancy grid generated by mapping |
| `/tf`, `/tf_static` | Coordinate-frame relationships |

## Save and finish

- [ ] Stop the robot. Keep Gazebo playing and mapping running.
- [ ] Run `bash scripts/run_ros_experiment.sh save`.
- [ ] Inspect `maps/first_room/map.yaml` and its referenced image, normally `map.pgm`. Both must exist and be nonempty; keep them together.
- [ ] Capture RViz and write brief observations beside the map: scan changes, movement/stop behavior, map growth, and errors.
- [ ] Close the controller, then press `Ctrl+C` in the mapping and Gazebo terminals.

For another run, move the existing map folder to an unused archive name before saving. The launcher refuses to overwrite it. Mapping follows the [ROBOTIS SLAM tutorial](https://docs.robotis.com/docs/systems/turtlebot3/simulation/slam_simulation/).

## Troubleshooting

| Symptom | Next check |
| --- | --- |
| Missing package | Source the right workspace; inspect `ros2 pkg prefix PACKAGE` |
| Compiler killed (`cc1plus`) | Close other heavy applications; limit both build levels to one job |
| Black Gazebo / spawn timeout | Allow initial model database loading to finish; retry spawning the absent robot below |
| Controller unresponsive | Focus its window, release keys after Space/Esc, and unpause Gazebo |
| Blank scan | Confirm an active publisher; choose Best Effort reliability for LaserScan |
| Blank map / TF errors | Confirm LiDAR, TF, advancing `/clock`, and `use_sim_time=true`; set RViz Fixed Frame to `map` |
| WSL `0x800705aa` | Check host memory/commit and WSL limits; free memory before retrying |

If the world is ready but the robot spawn timed out, run this in a prepared ROS terminal **only if the robot is absent**:

```bash
ros2 run gazebo_ros spawn_entity.py -entity waffle_pi \
  -file "$(ros2 pkg prefix --share turtlebot3_gazebo)/models/turtlebot3_waffle_pi/model.sdf" \
  -x -2.0 -y -0.5 -z 0.01 -timeout 120
```

`teleop-classic` is available for the original TurtleBot3 incremental-speed keyboard interface; unlike the game controller, releasing a key does not stop it.
